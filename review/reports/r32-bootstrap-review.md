# r32 bootstrap review and vector consumption

No blocking inconsistency was found in the r32 bootstrap changes. The fixed record occupies 87 bytes: 10-byte magic, one version byte, 16-byte salt, 12-byte nonce, 32-byte wrapped root, and 16-byte tag. The first 39 bytes form the complete GCM AAD. The spec's pre-KDF checks, UTF-8 password bound, fixed Argon2id parameters, and same-root rewrap requirements are mutually consistent with the supplied vectors.

Both INITIAL and REWRAP vectors were independently consumed by the Java implementation. Their published wrapping keys match actual Argon2id output; generated bootstrap bytes match every supplied byte; authenticated unwrap recovers the same published root for both passwords. Expected values are read from the supplied file, not regenerated by this implementation.

## Implementation and execution

[BootstrapV0.java](BootstrapV0.java) provides an in-memory codec:

- `unlock(file, charPassword)` encodes strict UTF-8 without normalization;
- `unlockBytes(file, passwordUtf8)` validates framing/password bounds before KDF, derives the key, authenticates the header, and returns root bytes only after GCM verification;
- `wrap(root, charPassword, SecureRandom)` generates fresh salt and nonce;
- `wrapBytes(root, passwordUtf8, salt, nonce)` is the explicit deterministic entry point used for vector reproduction.

Temporary password/key arrays controlled by the codec are cleared. Caller-owned inputs remain unchanged. This is a review implementation, not a claim of complete secret erasure by the JVM/provider.

The codec uses Bouncy Castle's Argon2id implementation with fixed v0 parameters and JCA AES/GCM. The tested Bouncy Castle version is 1.78.1, already present in the local Gradle distribution. The Gradle project dependencies were not changed and no download was required.

Run just the external bootstrap consumer:

```sh
bash review/run-bootstrap.sh
```

Or supply a vector-file path:

```sh
bash review/run-bootstrap.sh totp-vault-v0-r32-bootstrap-vectors.txt
```

Run all review suites:

```sh
bash review/run.sh
```

The bootstrap runner compiles in a temporary directory. It finds an installed bcprov JAR in common system/Nix Gradle locations, or accepts an explicit `BCPROV_JAR` environment variable. If the dependency is absent it fails with setup instructions; it never silently skips bootstrap tests. No package is fetched automatically.

```text

R32 vector REWRAP: Argon2id, exact 87-byte wrap, and authenticated unwrap match.
R32 PASS: 641 checks; 26 actual Argon2id evaluations; both external bootstrap vectors consumed.
```

The R32 cases cover:

- every published profile parameter and intermediate byte field;
- byte-exact salt/nonce/ciphertext/tag offsets and 39-byte AAD;
- seven incorrect record lengths, mutation of each magic byte, and all 255 unsupported version bytes, with KDF-call counters proving rejection before Argon2id;
- overlong UTF-8 passwords, malformed raw UTF-8 and unpaired UTF-16 surrogate rejection before KDF;
- empty passwords, exactly 1024 UTF-8 bytes, and composed/decomposed Unicode passwords remaining distinct;
- wrong passwords and mutations in salt, nonce, ciphertext, and tag, using the real KDF and requiring GCM authentication failure;
- wrong AAD boundaries using the published wrapping key, isolating AAD errors from KDF derivation;
- deterministic initial/rewrap bytes, unchanged root across the two published records, and an additional randomized wrapping round trip.

## Remaining scope

The codec does not write VAULT files, perform no-replace installation or atomic replacement, persist PENDING/ESTABLISHED identity pins, or inject filesystem/power-loss faults. Existing r20 establishment tests remain abstract evidence for those obligations. Integrating the codec into a client still requires the spec's durable publication and identity-pinning protocol.

The r32 text reports completion of a Java-to-Python semantic-object cross-check. That external implementation/artifact was not available in this workspace, so this review does not independently attest to that reported work. The new bootstrap consumer verifies the supplied vectors independently using Bouncy Castle/JCA; it is not a second independently authored Argon2 algorithm or a specialist cryptographic audit. The semantic field oracle is unchanged because r32 changes only bootstrap bytes and conformance requirements.
