# r31 byte-level executable review

The r31 review suite passed alongside all retained semantic and recovery regressions. The field/lifecycle oracle was not changed: r31 preserves its graph semantics. A new byte adapter feeds authenticated, decoded token histories into that oracle.

Run from the repository root with JDK 21 or later:

```sh
bash review/run.sh
```

The runner compiles in a temporary directory, downloads no dependencies, and runs r17, r20, r26, and r31. Optional seed/count arguments still apply only to the generated r20/r26 histories.

Recorded default results:

```text
R17: 38,267 checks passed.
R20: 16,473 checks passed.
R26: 12,355 checks passed; 2,949 differential views.
R31: 331 checks passed.
```

## New coverage

[R31Review.java](R31Review.java) provides a test-only encoder, registry validator, authenticated envelope reader, and conformance cases. TLV framing is read independently using ByteBuffer and DataInputStream; both readers feed the same registry validator. This is not two independently implemented complete parsers/validators.

| Area | Exercised cases |
|---|---|
| Top-level TLV | Exact integer/key/ID/signature widths; required/unknown/duplicate/out-of-order tags; type-specific forbidden tags; missing field assertions; truncated/trailing bytes; terminal signature position and complete-TLV omission in unsigned bytes |
| Parent encoding | Counts 0/1/32 accepted, 33 rejected; count mismatch; 31/33-byte IDs rejected; repeated/non-increasing IDs rejected; a 33-head semantic frontier remains intact while its proposed wire update is capacity-blocked |
| Strings | Each of ISSUER, ACCOUNT, DISPLAY_NAME: empty and 256-byte values, multibyte UTF-8 at the byte limit, 257-byte rejection, overlong encoding, surrogate encoding, out-of-range codepoint, isolated continuation byte |
| Atomic credential | All three algorithms and 6/7/8 digits; periods 1, 30, 2^31, 2^32-1; secret sizes 1/128 accepted and 0/129 rejected; unknown algorithms/digits; zero period; wrong widths; nested order, repetition, unknown/additional tags, and trailing bytes |
| Envelope | Exact 2048-byte files; 2032-byte authenticated plaintext; semantic lengths 0/1 frame successfully but fail semantic parsing; maximum v0 token/device sizes 1987/1532; generic capacity 2030; authenticated lengths 2031/65535 rejected before extraction; nonzero padding rejected |
| Processing order | Wrong file lengths rejected without invoking AEAD; bad tags rejected without semantic parsing; authenticated bad length/padding and identity mismatch rejected before semantic parsing |
| Future dispatch | Version 1 with unknown type and an opaque non-v0 tail is classified as future; a 2030-byte future payload is not rejected using the v0 maximum; malformed common prefix rejected; unknown type in version 0 rejected |
| Object crypto | Deterministic signing/encryption; signature type/vault domain separation; wrong filename ID, authenticated identity mismatch, modified ciphertext, and invalid signature; full token/device fixture reconstruction and round trip |
| TOTP | RFC 4226 counter 0/1/2 expected values at period starts/ends for 1, 30, 2^31, 2^32-1; all supported algorithm/digit combinations at a large period; negative time, zero/out-of-range period, and counter overflow rejected; unsigned 64-bit maximum counter accepted |
| Oracle adapter | Authenticated root, deletion, concurrent credential rotation, and resolution map raw IDs to symbolic identities; decoded history produces the expected conflict and then clears it |

The historical R17 TOTP helper now accepts a long period and checks the supported period/digit/time ranges. A separate BigInteger-time helper exercises the full unsigned 64-bit counter range. No UI warning threshold is introduced; large in-range periods remain valid.

The maximum-size objects are structurally valid signed fixtures. Their 32 arbitrary parent identities are not provided as a real dependency graph. Dependency validity is separately exercised by the decoded four-object history and the symbolic frontier tests.

## Pinned object vectors

[r31-object-vectors.txt](r31-object-vectors.txt) contains deterministic TOKEN_UPDATE and DEVICE_UPDATE root fixtures. All keys and seeds in this file are public test material. Each fixture records:

- root and signing seed/public key;
- HKDF extract and derived keys;
- canonical unsigned bytes, signature input, and signature;
- signed plaintext and content ID;
- object key, nonce, and associated data;
- complete padded envelope plaintext, ciphertext, and authentication tag.

Normal test runs reconstruct these values and compare them against the stored fixture file. They never regenerate expectations automatically. The R31Review `--write-vectors` mode is an explicit maintenance operation, run from the review directory after compilation, and should be used only when deliberately updating reviewed expectations.

These composed fixtures were generated by this implementation and then pinned. They detect later regressions but are not independently sourced known-answer vectors. Existing r17 RFC/HKDF/Ed25519 and AES-GCM primitive checks provide separate anchors. An independent implementation should consume these fixtures before interoperability is claimed.

## Remaining limits

This work does not implement the still-unfrozen VAULT bootstrap layout, Argon2/password-processing tests, production secret generation, presentation UI warnings/redaction, actual persistence fault injection, or the complete mandatory corpus. DEVICE_UPDATE framing/signature handling is covered, but a complete device-history validator is not added here. The strict Ed25519 arithmetic reused from r17 is test-only and not constant time.

The graph oracle intentionally remains an unbounded symbolic algorithm. Wire limits are enforced at the decoder/encoder boundary, where failure must not silently truncate a semantic frontier. The test bridge covers a small authenticated history, not exhaustive byte-to-graph fuzzing. The two framing readers share grammar enforcement, and the writer/decoder share registry assumptions. Independent full-parser validation and external review of the cryptographic construction remain outstanding.
